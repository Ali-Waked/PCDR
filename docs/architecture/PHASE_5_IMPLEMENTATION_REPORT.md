## A. نطاق العمل والعزل

- جرى العمل حصراً داخل `/root/PCDR/pcdr-phase5` وعلى الفرع `phase-5-workflows-communications-integrations`.
- لم يُعدّل المستودع الرئيسي `/root/PCDR` ولا شجرة العمل الأساسية؛ لم يُنفّذ `push` أو `merge` أو `rebase` أو `reset` أو `clean` أو حذف فروع/أشجار عمل.
- أُنشئ ملف `.env` محلي غير متتبّع داخل شجرة العمل فقط لتوفير مفتاح التشفير وقاعدة SQLite للتحقق؛ لم يُضق إلى Git ولم يُلمس ملف البيئة في المستودع الرئيسي.
- ظلّ الرأس `HEAD` عند الأساس المدمج حتى اكتمال جميع بوابات القبول، ثم أُنشئ الالتزام النهائي دون دفع.

## C. الحوكمة والقيود الثابتة

- صُنت أذونات RBAC المخصصة، والتدقيق، والوسائط، والإشعارات، والتوطين، ونظام التصميم الموجود.
- لم تُختلق حقائق مؤسسية أو موافقات أو أسماء مسؤولين أو تفويضات أو جهات استفادة أو شكاوى أو مانحين أو إنجازات.
- لم تُنشأ صلاحية تنتهي بـ `.approve`، ولا مسار موافقة، ولا تعيين مسؤول، ولا حالة موافقة مؤسسية.
- لم تُنشأ جداول `beneficiaries` أو `households` أو `complaints` أو `institutional_approvals` أو `delegations` أو `officeholders`.
- لم تُفتح بوابات الشكاوى المجهولة أو التتبع العام أو البيانات الحساسة أو القنوات الخارجية أو الويب هوكس؛ كلها `false` افتراضياً وتفشل مغلقة.
- لم تتغير حالات OQ-24 إلى OQ-29 ولا OQ-49، ولم تُقبل أي ADR جديد.

## D. النطاق الموثّق مقابل خارطة الطريق القديمة

تعرّف خارطة الطريق القديمة المرحلة الخامسة بأنها «شكاوى/متطوعون/وظائف/مناقصات». النطاق **الموثّق والمُنفّذ فعلياً** في هذا التسليم هو ما يرد في `docs/architecture/PHASE_5_CONTRACT.md`:

- سير العمل والمهام والتعاون الداخلي.
- المساءلة غير المحدِّدة والإحالات الآمنة ومراجعة المستندات.
- مركز الإشعارات والتفضيلات والتنبيهات والبريد داخلياً.
- الأتمتة المقيّدة بقوائم السماح، والتقويم المُجمِّع، ولوحة المعلومات وسجل النشاط.
- سجل التكاملات والويب هوكس مع بوابة أمان صريحة.

لم يُنفّذ أي استمارة عامة للشكاوى، ولا بيانات متطوعين/سير ذاتية/مناقصات، لأنها تتطلب قرارات OQ-26 وOQ-29 وغيرها. أُضيف تنبيه صريح في `IMPLEMENTATION_ROADMAP.md` لتوضيح أن العقد هو المرجع المختص بهذا التسليم.

## E. العقد المركزي والهجرة

- `config/phase5.php` هو المصدر الوحيد للبوابات، والحالات، والانتقالات، والحقول، والمعاملات، والأحداث، ومصادر التقويم، ولوحة المعلومات.
- أضافت الهجرة `2026_11_25_000100_create_phase5_operating_layer_schema.php` جداول سير العمل والمهام والتعاون والمساءلة والإحالات ومراجعة المستندات والإشعارات والأتمتة والتكاملات والويب هوكس و`domain_transitions`.
- `php artisan migrate:fresh --force` نجح. فحص قاعدة العملتين أظهر 124 جدولاً، ووجود جداول المرحلة الخامسة، وغياب جميع الجداول المحظورة.
- تقع النماذج والخدمات تحت `app/Models/Phase5` و`app/Services/Phase5`، وكل تغيير حساس يمر عبر `Phase5Authorization` و`AuditService`.

## F. RBAC والأمان

- `config/permissions.php` يضيف 47 صلاحية تقنية تحت الوحدة `phase5` دون أي مفتاح `.approve` أو تفويض.
- المسارات تطبّق `permission:<verb>` كحد أول، ثم تتحقق الخدمات من ملكية السجل/المشاركة/الصلاحية كحد ثانٍ.
- المستخدم غير المصرّح له يُرفض مغلّفاً؛ والوصول إلى السجلات الحساسة يتطلب صلاحية صريحة إضافية.
- `php artisan route:list` أظهر 439 مساراً غير تابع للبائعين، منها 64 مساراً للمرحلة الخامسة، و**صفر** مسار يحمل نص `approv`.

## G. سير العمل والمهام والتعاون

- تعريفات سير العمل مُنسّخة، والانتقالات معلنة مركزياً، وسجل `domain_transitions` يبقى append-only.
- المهام تدعم الإسناد، والحالة، والأولوية، والاعتماديات، وقائمة التحقق، والربط المسموح بالموارد فقط.
- التعاون الداخلي يشمل_threads والتعليقات والإشارات والمتابعة؛ والإشارة أو المتابعة **لا تمنح** صلاحية الوصول إلى السجل الأساسي.
- اختبارات المرحلة الخامسة تغطي منع الانتقال غير المعلن، وحقن الحقول غير المسموح بها، وعزل المستخدمين، وتنظيف المدخلات.

## H. المساءلة والإحالات والوثائق

- تُإنشاء حالات المساءلة برقم مرجعي آمن؛ الفئات المعلّقة تُرفض، ولا تُقبل الشكاوى المجهولة.
- التتبع العام يُعيد 404 ما لم تُفتح البوابة رسمياً؛ ولا توجد بيانات شخصية أو أسماء مستفيدين في الواجهة.
- الإحالات تحمل مرجعاً وحالة وأنواعاً وأوقاتاً فقط؛ لا تُعرض أسبابها أو نصوصها المصدرية في الفهرس أو الإشعارات.
- مراجعة المستندات تستخدم الوسائط المقيدة والرابط الموقّع `public.operational-documents.download` بشرط صلاحية `documents.download`.

## I. الإشعارات والأتمتة

- الإشعارات تستخدم مفاتيح عنوان ومعاينة آمنة فقط؛ لا نصوص شكاوى ولا بيانات قابلة للتحديد.
- القنوات SMS وWhatsApp معطّلة عبر `DisabledNotificationAdapter`؛ ولا يُادّعى تسليم خارجي دون تأكيد المزوّد.
- الأتمتة تسمح فقط بحقول ومعاملات وإجراءات معلنة في `config/phase5.php`، مع حد أقصى للشروط/الإجراءات والمحاولات والمهلة، دون أي تنفيذ برمجي أو SQL أو shell.
- `phase5:scan-deadlines` يُصدر أحداث استحقاق محددة:idempotent وذات مستلمين مصرّح لهم فقط. أُضيفت الأحداث الأربعة (`workflow.step_due_soon`, `workflow.step_overdue`, `referral.due_soon`, `referral.overdue`) إلى محفّزات الأتمتة وقائمة أحداث الويب هوكس.

## J. التقويم واللوحة وسجل النشاط

- التقويم يقرأ التواريخ من الجداول المصرّح بها فقط ضمن سقف 500 حدث، ولا ينشئ متجر تواريخ منفصلاً.
- اللوحة تعرض عدّادات مجمّعة حسب الصلاحية، وحالات البوابات، وإشعار خصوصية؛ ولا تعرض معرّفات أو نصوصاً حساسة.
- سجل النشاط يعرض مفاتيح الإجراءات والمعرّفات التقنية فقط، مع إخفاء ما لا يملك المستخدم صلاحية رؤيته.

## K. التكاملات والويب هوكس

- تُسجّل التكاملات معطّلة افتراضياً، ولا تُرسل بيانات إلى وجهات غير مصرّح بها.
- وجهات الويب هوكس الخارجية تخضع لـ HTTPS ورفض العناوين الخاصة/الحلقية/الارتباط المحلي/البيانات الوصفية.
- الاستقبال يتطلب HMAC وتسامحاً زمنياً 300 ثانية و nonce لمنع إعادة الإرسال وتحديد معدل الطلبات.
- البوابة `webhooks_enabled` مغلقة افتراضياً؛ إنشاء نقاط الاستقبال وإعادة الإرسال غير متاحين قبل قرار رسمي.

## L. الواجهة الأمامية

- أُنشئت 17 صفحة Inertia/Vue وفق العقد، مع ستة مكوّنات مشتركة ووحدة `phase5.js` للمسارات والتسميات والتنسيق.
- لا تعتمد الواجهة على Ziggy؛ `phase5Url()` يستخدم `route()` إن وُجدت وإلا يعيد البناء إلى `/{locale}/operations/phase5/...`.
- أُضيفت مجموعة تنقل «الطبقة التشغيلية الخامسة» إلى `CmsLayout.vue` مع تصفية الروابط حسب الصلاحية.
- الصفحات ثنائية اللغة وتستخدم خصائص CSS منطقية لدعم RTL/LTR، مع حالات فراغ وهيكلة جداول مستجيبة.
- `npm run build` نجح: 697 وحدة. التحذيرات الواردة اختيارية (`fontaine`) أو تتعلق بحجم الحزمة فقط.

## O. العيوب المكتشفة والمعالجة

1.\,\`Phase5Support::reference()` كان يمرّر كائن ULID؛ أُضيف تحويل صريح إلى نص.
2. مُنشئ `Phase5ScanDeadlines` لم يستدعِ `parent::__construct()`؛ أُصلح.
3. تعيينات موارد `Phase5Authorization` كانت غير مكتملة؛ أُكملت.
4. مراجعة المستندات كانت تخفي السجل عن مُقدّمه؛ أُصلح مع الحفاظ على عزل الآخرين.
5. جدول مصدر الإحالة كان غير مطابق للمخطط؛ أُصلح، وأُزيل `operational_record` من مصادر الإحالة غير القابلة للعنونة.
6. مفهرس المساءلة افتقر إلى `id` اللازم لرابط التفاصيل؛ أُضيف دون كشف بيانات حساسة.
7. صفحات Inertia المكتشفة حديثاً كشفت ثلاثة أنواع من تعارضات `assertInertia` مع إصدار Inertia المثبّت؛ حُوّلت اختبارات المجموعات إلى `Collection->all()` مع الحفاظ على نفس المعنى.
8. أحداث الاستحقاق لم تكن مدرجة في قوائم السماح؛ أُضيفت إلى الأتمتة والويب هوكس.
9. مسار لوحة المرحلة الخامسة كان يُبنى خاطئاً في بديل `phase5Url()`؛ أُصلح إلى `/dashboard`.

## P. الخصوصية — OQ-24 إلى OQ-29

جميع البوابات الحساسة مغلقة، ولا توجد بنية بيانات شخصية أو شكاوى مجهولة أو تتبع عام مُفعّل. حالات OQ-24 إلى OQ-29 **لم تتغير** وما زالت عوائق أمام أي مخطط حساس أو استمارة عامة؛ سُجّلت كقيود لا كإنجاز.

## Q. السلطة المؤسسية — OQ-49

لا توجد صلاحية `.approve` ولا مسار موافقة ولا تفويض أو تعيين مسؤول. تُبقى الحالة **PARTIALLY RESOLVED — PENDING FORMAL APPROVAL** كما هي. أي انتقال مرحلة أو قبول ADR يتطلب تفويضاً كتابياً رسمياً خارج هذا التنفيذ.

## R. القيود والمتبقي

- هذه طبقة تشغيل تقنية عامة ولا تعني اكتمال أي خلية في مصفوفة التتبع الاستراتيجي.
- لم تُنفّذ استمارات عامة للشكاوى أو المتطوعين أو الوظائف أو المناقصات؛ ولا بنية احتفاظ أو حذف شخصي.
- لا يوجد اختبار متصفح أو اختبار مكوّنات Vue أو فحص وصولية آلي في هذه المرحلة.
- تحذير حجم حزمة JavaScript وغياب حزمة `fontaine` الاختيارية لا يؤثران على البناء.
- أي تشغيل إنتاجي يخضع لبوابة النشر في `DEPLOYMENT_ARCHITECTURE.md` §8؛ لم يُنجز هنا ولم يُصرّح به.
